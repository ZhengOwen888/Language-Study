# 1.3 The Network Core

> **Big Idea:** The "core" = the mesh of routers/switches and links connecting all the end systems together (as opposed to the "edge," which is the end systems themselves). Two ways to move data through this core: **packet switching** and **circuit switching**.

---

## 1.3.1 Packet Switching

> **What is a "link"?** a **communication liink** is just the physical connection (wire, fiber, radio channel) between two devices - e.g., between an end system and a router, or between two routers. Every link has a **transmission rate r** (its "speed," in bits per second) - this is basically how fast data can be pushed onto that specific wire. A packet's full path from source to destination is usually made up of SEVERAL links chained together, one for each hop through a router.

- Messages are broken into **packets**, sent independently through links + packet switches (routers/link-layer switches), reassembled at the destination.
- **Transmission time** for a packet of **L** bits over a link with rate **r** bps: `L/R` seconds.

### Store-and-Forward Transmission
> A packet switch must receive the **ENTIRE packet** before forwarding **any** of it onward (it buffers/"stores" first, then "forwards").

- **1 router, 1 packet:** total delay = `2L/R` (L/R to receive fully at router + L/R to forward to destination). Ignores propagation delay (covered in 1.4).
- **General formula (N links, ignoring propagation delay):**
$$d_{end\text{-}\text{-}end} = \frac{NL}{R}$$

#### What this formula actually represents (and why it matters)
This formula answers: **"How long does it take one packet to travel completely from the source to the destination, hopping through N links?"** It matters because it's the foundation for basically every delay/timing homework problem in this chapter - once your understand where each piece comes from, the more complex formulas in Section 1.4 (which add propagation delay, processing delay, etc.) are just building on top of this same idea.

**Why it's `NL/R` and not `L/R`:** Because of store-and-forward - the packet has to be fully received and then fully re-sent at EACH router along the way. So the SAME `L/R` delay repeats once for every link the packet crosses, and there are N links total -> hence `N x (L/R)`

#### Breaking down each variable

| Variable | What it represents | How do you find it in a problem |
|---|---|---|
| **N** | The number of **links** the packet travels across from source to destination (NOT the number of routers - there's always one fewer router than links, since routers sit *between* links). | Count the number of "hops"/wires along the path shown in the problem/diagram. E.g., Source -> Router -> Destination = 2 links (N=2), Source -> R1 -> R2 -> Destination = 3 links (N=3). |
| **L** | The **size of the packet**, in bits. | Usually given directly in the problem (e.g., "a packet of 1,000 bits"). If given in byts, convert: multiply by 8 (1 byte = 8 bits.) |
| **R** | The **transmission rate** of the link, in bits per second (bps). | Given directly (e.g., "a 10 Mbps link"). The formula assumes **every link has the SAME rate R** - if a problem gives different rate for different links, you can't use this simple version, you'd instead add up `L/R` seperately for each link using its own rate. |

> **Quick sanity check trick:** Each `L/R` term = "time to fully push one packet's worth of bits onto one link." Since the packet gets fully sotred-and-then-forwarded at every router, you're really just adding up that same "push time" once per link - that's all `NL/R` is doing.

### Queing Delay and Packet Loss
- Each router has an **output buffer/queue** per link.
- If a packet arrives while the link is busy -> it **waits in the queue** (queuing delay - variable, depends on congestion).
- If the buffer is **full** -> **packet loss** (packet gets dropped)
- Analogy: waiting in line at a bank teller or tollbooth.

### Forwarding Tables and Routing Protocols
- Every end system has an **IP address** (hierarchicalm like a postal address).
- Each Router has a **forwarding table**: maps destination address -> outbound link.
- Router checks incoming packet's destination address against its table -> sends packet out the matching link.
- **Routing protocols** automatically configure these forwarding tables (e.g., by computing shortest paths) - covered in depth in Ch. 5.
- Analogy: like asking for directions at each gas station along a road trip - each "router" (attendant) only needs to know the next step, not the whole route.

## 1.3.2 Cicuit Switching

> **What is a "circuit"?** A circuit is a dedicated, reserved connection between the sender and receiver - set up BEFORE any data is sent, and held open for the entire communication session. It's not a seperate physical wire just for you; it's a **reserveed portion of a link's capacity** (a specific frequency band or a specific time slot, depending on the multiplecing method) that only your connection is allowed to use for as long as the session lasts. Every switch along the path keeps track of ("Maintains state for") this circuit so it knows to keep reserving that same slice of bandwidth for you. Once the session ends, the circuit is torn fown and that reserved capacity becomes available for someone else.

> In circuit switching, resources (bandwidth, buffers) are **reserved in advance** for the entire session. In packet switching, resources are used **on-demand** (no reversation -> possible waiting).

**Analogy:** Circuit switching = a restaurant that takes reservations (hassle upfront, but guaranteed seat on arrival). Packet switching = walk-in restaurant (no upfront hassle, but might wait for a table).

- Traditinoal telephone networks = classic circuit-switched example.
- A dedicated **circuit** is set up sender->receiver, a ** constant reserved transmission rate** is guaranteed for the whole call.

### Multiplexing: FDM vs. TDM

> **What is "multiplexing"?** It's just a fancy word for **sharing one physical link among multiple connections** at the same time, without them interfering with each other. FDM and TDM are the two ways circuit switching actually does this sharing.

| | **FDM** (Frequency-Division Multiplexing) | **TDM** (Time-Division Multiplexing) |
|---|---|---|
| How it splits the link | Divides the **frequency spectrum** - each connection gets its own dedicated frequency band, all running **at the same time**, forever, for the whole call | Divides **time** into repeating frames; each frame is cut into slots, and one specific slot number is reserved for your connection in **every** frame. |
| Simple picture | Like several radio stations broadcasting at the same time, each on its own frequency - you just tune to a different "channel" to hear a different one | Like a rotating turn-taking system - connection #1 gets to use the FULL link during slot 2, and so on, repeating over and over |
| Example | Telephone lines (4 kHz bands each); FM radio stations | Telephone/data lines split into repeating time frames. |

#### The TDM rate formula - What it actually means

$$\text{Circuit's transmission rate} = (\text{frame rate}) \times (\text{bits per slot})$$

**What problem this solves:** With TDM, your connection doesn't get to use the link 100% of the time - it only gets ONE slot out of every frame. This formula tells you **how fast data effectively moves for YOUR specific connection**, once you account for the fact that you're only "on" for a tiny sliver of each frame.

**Where each number comes from:**
| Variable | What it means | How to find it |
|---|---|---|
| **Frame rate** | How many frames go by per second (i.e., how many times per second your slot comes back around) | Usually given directly in the problem (e.g., "8,000 frames per second") |
| **Bits per slot** | How many bits fit into ONE slot (i.e., how much data you can send during your one turn) | Usually given directly (e.g., "each slot = 8 bits") |

**Worked example:** If the link sends **8,000 frames per second**, and each slot holds **8 bits**, then:
`8,000 frames/sec * 8 bits/slot = 64,000 bits/sec = 64 kbps` -> That 64kbps is the effective, guarantieed speed of YOUR one circuit - even though the full physical link is running much faster than that overall (since it's also carrying everyone else's slots).

> **What is "circuit setup" (a.k.a. circuit establishment)?** Before ANY data can travel in circuit switching, the network first has to physically **reserve** the circuit - meaning every switch along the path from sender to receiver has to agree to set aside a specific slot/frequency band JUST for this handshake-and-reservation process takes real time, and that time is called **circuit setup time** (or setup delay) - it's essentially the "hassle of calling ahead for a resturant reservation" from our earlier analog. It's a delay that happens ONCE, before transmission even starts, and it's a cost that packet switching simply doesn't have (since packet switching never reserves anything in advance).

**Numerical example:** Sending 640,000 bits, TDM with 24 slots, link rate 1.536 Mbps, circuit setup time = 500 ms:
- Each circuit's rate = 1.536 Mbps / 24 = **64 kbps**
- Transmit time = 640,000 bits / 64 kbps = **10 sec**
- Total time = 10 sec (transmitting) + 0.5 sec (circuit setup, happens first) = **10.5 sec**
- Transmission time does NOT depend on number of links in circuit switching (unlike packet switching's `NL/R`).

### Packet Switching vs. Circuit Switching - Why Packet Switching "Wins" (usually)

| | Circuit Switching | Packet Switching |
|---|---|---|
| Resource allocation | Reserved in adavnce (guaranteed) | On-demand (shared) |
| Efficiency | **Wasteful** - reserved capacity sits idle during silence/pauses | **More efficient** - supports MORE users on same link because not everyone is active at once |
| Predictability | Predictable, constant delay | Variable/unpredictable delay (queuing) |
| Good for | Real-time, guaranteed-quality needs (their argument) | Bursty data traffic (most Internet use) |
| Setup | Requires complex signaling to set up circuit first | No setup - just send |

> **Core intuition from the book's numeric examples:** With circuit switching, a 1 Mbps link split for 100 kbps users can only support exactly **10** simultaneous users. With packet switching, the same link can support **35 users** (each active only 10% of the time) with almost no performance loss, because packet switching shares capacity dynamically instead of pre-reserving it per user. This is THE core argument for why packet switching is more efficient.

> **Trend:** The Internet (and even modern telephone networks) is moving toward packet switching over time.

## 1.3.3 A Network of Networks

> **Core question:** How are all the world's ISPs interconnected so any end system can reach any other end system? Answer: it's a **"network of networks"**.

Building up the real Internet structure step-by-step:

| Structure | Description |
|---|---|
| Native "mesh" idea | Every access ISP connects directly to every other access ISP -> way too costly (hundreds of thousands of ISPs) |
| **Structure 1** | All access ISPs connect to ONE global transit ISP. Access ISP = **customer**, global ISP = **provider** (customer pays provider). |
| **Structure 2** | Multiple COMPETING global transit ISPs (2-tier hierarchy). These global ISPs must interconnect with each other too. |
| **Structure 3** | More realistic: adds **regional ISPs** (mid-tier) between access ISPs and **Tier-1 ISPs** (the "top" - ~12 exist today, e.g., Level 3, AT&T, Sprint, NTT). Access ISP -> Regional ISP -> Tier-1 ISP. |
| **Structure 4** | Adds: **PoPs**, **multi-homing**, **peering**, **IXPs** (defined below). |
| **Structure 5** (today's real Internet) | Structure 4 + **Content Provider networks** (e.g., Google's own private global network).

### Key Vocabulary
| Term | Definition |
|---|---|
| **Tier-1 ISP** | Top of the hierarchy - massive ISPs with (near-)global reach. No one "offcially" certifies tier-1 status. They peer with each other for free. |
| **PoP (Point of Presence)** | A group of routers (same location) in a provider's network where customer ISPs connect in. |
| **Multi-homing** | An ISP connects to **2+ provider ISPs** at once (for backup - if one provider fails, it still has Internet access). |
| **Peering** | Two ISPs at the SAME tier directly connect to each other, **settlement-free** (neither pays the other) - cuts costs by skipping the upstream provider. |
| **IXP (Internet Exchange Point)** | A physical building/location where MULTIPLE ISPs meet to peer with each other. 600+ exist today. |

> **Customer-Provider relationship:** the customer PAYS the provider. Access ISP pays Regional ISP; Regional ISP pays Tier-1 ISP. Tier-1 ISPs pays no one (top of the chain) - they just peer with each other for free.

> **Google example (Structure 5):** Google built its OWN private global network connecting its data centers. It tries to "bypass" expensive upper-tier ISPs by peering directly (free) with lower-tier ISPs or at IXPs - but still has to pay Tier-1 ISPs for the access ISPs it can only reach that way.

## Supplementary: Binomial Probability for Statistical Multiplexing

> This connects directly to the packet-switching efficiency argument above (remember: "35 users can share a link that circuit switching could only give to 10 users"?). This is the actual math used to CALCULATE that kind of claim precisely, instead of just estimating it.

### The Binomial Random Variable - What It's For

You use this whenever you have **many independent yes/no events** (like "is this host active or not?") and you want the probability that a SPECIFIC NUMBER of them turn out "yes."

**Setup:**
- You run **n** independent experiments (e.g., n = 3- hosts, and "is this host active right now?").
- Each experiment **succeeds** (e.g., "host is active") with probability **p**.
- Each experiment **fails** (e.g., "host is idle") with probability **1 - p**.
- **X** = the random variable = the number of successes (active hosts) out of the n experiments.

### The Formula

$$P(X = i) = \binom{n}{i} p^i (1-p)^{n-i}$$

| Part | What it represents | Plain-English meaning |
|---|---|---|
| $\binom{n}{i}$ ("n choose i") | The number of DIFFERENT ways to pick which `i` experiments (out of n) are the successful ones | "How many different combinations of hosts could be the active ones?" |
| $p^i$ | Probability that those specific `i` experiments ALL succeed | "How likely is it that exactly these `i` hosts are all active?" |
| $(1-p)^{n-i}$ | Probability that the remaning `n-i` experiment ALL fail | "How likely is it that all the other hosts are idle?" |

> **Why we multiply all three together:** We need ALL THREE things to be true at once (i specific hosts active AND the rest idle AND accounting for every possible combination of which hosts those are) - and multiplying probabilities is how you combine independent "AND" conditions.

### 📝 Worked Exercise (exactly the kind of problem you'll see in homework)

**Setup:** N = 30 hosts share one access link with total capacity 10 Mbps. Each host needs 1 Mbps **only when active**, and each host is active **20% of the time** (independently of the others). **Question:** What is the probability that **MORE than 10** hosts are simultaneously active? (This matters because if more than 10 hosts are active at once, they'd need more than 10 Mbps total — more than the link can handle!)

**Mapping this problem onto the formula:**

| Formula variable | Value in this problem |
|---|---|
| n (number of experiments) | 30 (number of hosts) |
| p (success probability) | 0.2 (20% chance any one host is active) |
| 1 − p (failure probability) | 0.8 (80% chance a host is idle) |
| X | Number of simultaneously active hosts |
| What we want | P(X > 10) |

#### Method 1: Direct Sum
Add up the probability of EVERY possible "overload" scenario — 11 active hosts, OR 12 active, OR ... all the way up to 30 active:

$$P(X > 10) = \sum_{i=11}^{30} \binom{30}{i} (0.2)^i (0.8)^{30-i}$$

= $\binom{30}{11}(0.2)^{11}(0.8)^{19} + \binom{30}{12}(0.2)^{12}(0.8)^{18} + \dots + \binom{30}{30}(0.2)^{30}(0.8)^{0}$

📌 This works but requires adding up **20 separate terms** (i = 11 through 30) — tedious.

#### Method 2: Complement Rule (much faster!)

> **Key idea:** Instead of adding up all the ways it CAN go wrong (11 through 30 active), it's easier to calculate the probability it goes FINE (0 through 10 active) and subtract that from 1. `P(X > 10) = 1 − P(X ≤ 10)`

$$P(X > 10) = 1 - \sum_{i=0}^{10} \binom{30}{i}(0.2)^i(0.8)^{30-i}$$

= $1 - \Big[\binom{30}{0}(0.2)^0(0.8)^{30} + \binom{30}{1}(0.2)^1(0.8)^{29} + \dots + \binom{30}{10}(0.2)^{10}(0.8)^{20}\Big]$

## Quick Review — Key Takeaways (Section 1.3)

- **Store-and-forward**: a router must receive the WHOLE packet before sending any of it onward. Formula: `d = NL/R`.
- **Queuing delay** happens when a link is busy; **packet loss** happens when the buffer is full.
- **Forwarding tables** (destination address → outbound link) let routers move packets; **routing protocols** set these tables automatically.
- **Circuit switching** = reserved resources for the whole session (e.g., phone calls); **packet switching** = on-demand, shared, no reservation (e.g., the Internet).
- **FDM** splits by frequency; **TDM** splits by time slots.
- Packet switching is generally **more efficient** than circuit switching because it shares capacity dynamically instead of wasting reserved-but-unused bandwidth.
- The Internet = a **"network of networks"**: Access ISPs → Regional ISPs → Tier-1 ISPs, plus PoPs, multi-homing, peering, IXPs, and (today) Content Provider networks like Google's.
- **Customers pay providers**; **peers don't pay each other** (settlement-free).

## Goals of IO Software
1. **Device independence** - ability to write a program that can access any IO device without having to specifying which it is in advance.

2. **Uniform naming** - all files and devices are addressed via a path name independent of the specific device it is.

3. **Error handling** - all error handling should be handled as close to the hardware as possible

4. **synchronous (blocking) vs asynchronous** - asynchronous is interrupt driven, this means the CPU is allowed to go do another job while waiting for IO. Most user  programs are written with synchronous IO operations because they are much easier to write. However most physical hardware is asynchronous and the OS just make thme look synchronous for the user.

5. **Buffering** - a temporary holding area in computer memory to store data that arrives from a device.

## Programmed IO
The CPU manages all IO operations by executing instructions for every byte or word that is transferred. This heavily relies on busy waiting which could decrese CPU Utilization.

## Interrupt Driven IO
Instead of having the CPU wait until all characters are used, we allow the CPU to perform context switch while waiting for IO and comes back when signaled by the device that it needs more data. This is still horrible as the interrupts happen for every character and performing interrupts take time so CPU time is still wasted.

## IO With DMA
CPU basically hands all the IO work to the DMA and DMA will notify the CPU when it is done, only one interrupt for the CPU. However if the DMA is slower than the device, then the performance will still be slow.

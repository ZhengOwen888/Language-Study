## 5.1.1 IO Devices

IO Devices can be seperated into two categories:

**Block Devices**
- IO devices that store information in fixed memory sizes (ex. the disk)

**Character Device**
- IO devices that accepts a stream of characters (ex. the keyboard)

**exception**: There are some IO devices like the clock that does't store information in fixed memory sizes or accpet a stream of characters, but generally these categories cover for most IO devices.

## 5.1.2 Device Controller
A IO device consists of the mechanical parts and a electronic part. The electronic part is called the device controller, usually a chip that that contains the program to control how the mechanical part of the IO device behaves.

Device Controller's Job:
- Converst streams of bits into a block of bytes.
- Perform error corrections.
- Block of Bytes are copied to main memory.

## 5.1.2 Memory Mapped IO
Controllers communicate with the CPU via **control registers** and **data buffers**. The OS reads/writes these to command devices and query state. The key question is, how does the CPU address these registers?

### Approach 1: Seperate IO Port Space
Each control register is assigned an IO port number. This requires 2 seperate address spaces, one fore the main memory and one for the IO ports The CPU uses dedicated intructions:
- ```IN REG, PORT``` - read from IO port to CPU register.
- ```OUT PORT, REG``` - write CPU register to IO port.

> [!Note]
> Memory and IO have seperate address spaces, this is used by IBM 360 and the ones that came before it.

### Approach 2: Memory Mapped IO
All control registers are mapped into a single address space along with the main memory. This means the IO ports will share a single adderss space with the main memory. Some memory address will be reserved for the IO Ports but most will be for the main memory.

### Approach 3: Hybrid
It is possible to combine both approaches as the third.

### Advantages of Memory Mapped IO
| Advantage | Detail |
|---|---|
| No assembly required | Device registers are just memory variables, drivers can be written entirely in C. Port based IO still requires IN and OUT assembly intructions. |
| Simpler Protection | OS prevents user virtual address from seeing device register pages. |
| Memory Intructions | Every intructions that can reference memory, can access control register |
| Makes checking device status more efficient | Intructions like ```TEST``` can directly check a control register for 0 (0 means ready)|

```
LOOP:
    TEST PORT_4
    BEQ READY
    BRANCH LOOP
READY:
```

### Disadvantages of Memory Mapped IO
| Disadvantage | Detail |
|---|---|
| Caching conflicts | Controled registers must not be cached, a cached register value never updates because it will no longer pull updated data from the hardware. OS need to diable caching for control registers. |
| Multiple bus problem | There are two buses, one for the RAM and one for the IO devices, CPU sends address to fast bus leading to RAM and the slow bus that leads to the devices will never pick it up.|

### Solutions to the Multiple bus problem.
1. **Memory first, fallback** - The CPU will ask RAM first, if the RAM said that its not their address then the CPU then tries the other buses where the devices live. This works but everything takes 2 attempt at worst.

2. **Snooping device** - you put a middle man on the RAM bus that eavesdrop on address that pass though and foward the relevant ones to the devices. The only problem is that the RAM buses are very fast so the middleman can't keep up.

3. **Memory Controller Filtering** - At boot time, OS tells memory controller the range of address that belong to devices. The MMU will then handle the sorting.

## 5.1.3 Direct Memory Access (DMA)
When the CPU wants to read data from a disk, it normally has to fetch it one byte at a time in a loop and read one byte from the device, store it in RAM, and then repeat this thousands of times. This wastes the CPU's time when it could be doing more useful work.

DMA offloads this job to a dedicated chip, the DMA controller, so that that the CPU can go do other things while the data is moved.

**DMA controller** is a seperate chip on the motherboard that can access the bus on its own, independently of the CPU. It has a few registers the CPU can program:
- **Memory address register** - where in RAM to put the data.
- **Byte count register** - how much data to transfer.
- **Control registers** - which device, which direcition (read or write), how many bytes at a time.

**Disk read without DMA**
1. Disk reads data into its own internal buffer
2. Disk controller checks for errors (checksum)
3. Disk controller interrupts the CPU.
4. CPU loops, reading one byte/word at a time from the device into RAM

> [!Note]
> The CPU is stuck doing all the moving work itself.

**Disk read with DMA**
1. CPU programs the DMA controller (memory address registers, byte count register, and the control registers)
2. DMA controller makes a requests to  disk controller to initiate the transfer to memory from the internal buffer of disk controller.
3. Disk controller writes to memory.
4. Disk controller notifies the DMA controller by sending an acknowledgement.
5. DMA controller repeats until all is done.
6. DMA raises interrupt to CPU to signify that it is done.

**Why does the disk buffer data internally first?**
- **Error checking** - The disk needs to read the whole block and verify the checksum before sending anything. If there's an error, nothing gets written to RAM at all. You can't do this mid stream.

- **Timing** - Bits come from the disk at a constant rate whether anyone is ready or not. If the bus is busy, there's nowhere to put the incoming bits. The internal buffer acts as a waiting room where it holds everything safely until the bus is free.

**Transfer Modes**
- **Word at a Time (cycle stealing)** - The DMA controller grabs the bus for one word, transfer it, then releases the bus. The CPU can use the bus between transfers but gets slightly delayed each time the DMA steals a cycle

> [!Note] Like someone occasionally cutting (stealing your spot) in front of you in a queue, then leaving

- **Block mode (burst mode)** - The DMA controller takes the bus and holds it for an entire burst of data before releasing it. More efficient (acquiring the bus takes overhead, so doing it once for many words is better) but the CPU and other devices are completely blocked for the duration.

> [!Note] Like someone taking over the entire queue for a long time

**Formula to calculate total time to transfer data with DMA**
```
// General Fomula
T = Tcmd + Tdata + Tack

// Word at a Time
Tword(N) = 3N * (t1 + t2)

// 1. Command: The DMA controller acquires the bus(t1) and sends the "Send me data" command(t2) to the disk.
// 2. Data: The disk controller acquires the bus(t1) and sends one word(t2) of data to memory.
// 3. Ack: The DMA controller acquires the bus again(t1) to send the "Recieved acknowledgement"(t2).

// Burst Mode
Tburst(N) = (t1 + t2) + (t1 + N * t2) + (t1 + t2)
          = 3(t1) + (N + 2)(t2)

// 1. Command: The DMA controller acquires the bus once(t1) and send the "Send me data" command(t2) to the disk.
// 2. The disk controller acuiqres the bus once(t1) and send all N words to memory(N * t2).
// 3. The DMA controller acquires the bus one final time(t1) and send the "Recieved acknowledgement"(t2).
```
- N - number of words.
- t1 - bus acquisition time.
- t2 - time to transfer one word.
- Tcmd - time to send the cmd.
- Tdata - time to send the data.
- Tack - time to send the acknowledgement.

## 1.1.0 Objectives
- Understand what is the difference between user space and kernel space.
- Understand what a process is, how it's created and terminated.
- Understand what the possible states and transitions are for a process.
- Understand how process interrupt is handled.
- Understand how to calculate cpu utilization.

## 1.1.1 User Space and Kernel Space
User Space
- This is where the application and user software runs.
- Does not have direct access to hardware, and must make a system call to the kernel.
- A crash here only affects specific applications.

Kernel Space
- This is where the core operating system runs.
- It manages the hardware, memory process scheduling, security and more.
- Has direct access to the hardware.
- A crash here will crash the whole system.

## 1.1.2 What is a Process
A process is simply an instance of a running program executed by the operating system. It includes everything it needs to run including, the program counter, registers, and data. A process can have exactly one parent process and can have 0 or more child processes. (Parent Process - one who creates, Child Process - one who was created)

## 1.1.3 Process Creation, Termination and States
Events That Cause Process Creation
- System Initialization - When you first boot up the system.
- A running process makes a system call to create another process.
- A user request to create a new process.
- Initilization of a batch job.

Events That Cause Process Termination
- Normal exit (voluntary)
- Error exit (voluntary)
- Fatal error (involuntary)
- Killed by another process (involuntary)

Possible Process States
- Running - Actually using the CPU at that instant.
- Ready - Runnable, temporarily stopped to let another process run.
- Blocked - unable to run until some external events happen, like waiting for I/O or data.

Possible Process State Transitions
- Ready -> Running (Process is selected to run)
- Running -> Ready (Process timed out, some other higher priority or scheduled process arrived)
- Running -> Blocked (Resource not immediately met, or waiting for IO or some event to happen)
- Blocked -> Ready (Resource is met)

## 1.1.4 Process Implementation
To implement a process, we need to keep track of all the imformation it needs. We can use a array of structures call the Process Control Block (PCB), where every entry represents one process.

Each entry contains a process's states (a few listed):
- Registers
- Program counter (PC)
- Program status word (PSW)
- Stack pointer
- Process state
- Priority

## 1.1.5 Handling Process Interrupt (In Multiprogramming)

Multiprogramming is when the CPU rapidly switch from process to process when one process is waiting or interrupted. This gives the illusion of parallelism when one CPU is present, in reality only one process runs at a time.

How process interrupt is handled:
1. Hardware stacks the program counter and other status registers onto the kernel stack.
2. Hardware loads new program counter from the interrupt vector table for the specific interrupt handler.
3. Assembly routine saves registers and other volatile information onto the process control block(PCB).
4. Assembly routine sets up new stack for the C interrupt handler.
5. C interrupt service runs.
6. Scheduler decides which processs to run next from the ready queue.
7. C interrupt service returns to the assembly code.
8. Assembly procedure pops saved program counter, program status word and registers from the new stack into the CPU, and start up the new current process. (Context Switch)

## 1.1.6 CPU Utilization

IO Bound Tasks - Tasks that are limited by I/O speed, spends most time on waiting for data.

CPU Bound Tasks - Tasks that are limited by processing power, spends most time in CPU doing computations.

In theory if one process uses the CPU 20% of the time, then 5 processes should keep the CPU busy all the time. However, this assumes that at least one process is ready, but in reality more than one process could be blocked or waiting for an event like I/O to happen.

A Better way:
```
CPU Utilization = 1 - p^n
```
- p = fraction of time a process spends on I/O
- n = The number of processes in memory
- p^n = The probability that all n processes are waiting for I/O

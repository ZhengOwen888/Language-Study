## 1.4.0 Objectives
- Understand the different categories and types of scheduling algorithms.
- Understand scheduling algorithms for batch systems, interactive systems, and real time systems.

## 1.4.1 Categories of Scheduling Algorithms
The goal of all systems:
- Fairness - giving each process a fair share of the CPU.
- Policy enforcement - seeing that stated policy is carried out.
- Balance - keeping all parts of the system busy.

**Batch System**
- Goal: Maximize the number of jobs per hour.

**Interactive Systems**
- Goal: Responds quickly to users.

**Real Time Systems**
- Goal: Meeting the deadline for every task.

## 1.4.2 Types of Scheduling Algorithms
**Nonpreemptive**
- Picks a process to run, lets it run until it blocks or voluntarily releases the CPU. It will not be forcibly suspended even if it runs for hours.

**Preemptive**
- Picks a process to run, lets it run for a maximum of some fixed time. If it is still running at the end of the time interval, it is suspended and the scheduler picks another process to run (if one is available).

## 1.4.3 Important Concepts

**Throughput**
- The number of jobs per hour that the system completes.

**Turnaround Time**
- The statistical average time from the moment that a batch job is submitted until the moment it is completed. It measures how long the average user has to wait for the output.
```
Turnaround Time = Completion Time - Arrival Time
```

**Response Time**
- The time between a issuing a command and getting the result.
```
Response Time = First Response Time - Arrival Time
```

**Proportionality**
- Meeting the users' expectation of how long a task takes.

## 1.4.4 Scheduling in Batch System

### First Come First Serve
Processes are assigned the CPU in the order they request it. There is a single queue of ready processes. When the running process blocks, the next ready in the queue is run. when the blocked process is no longer blocked it goes to the back of the queue.

### Shortest Job
Running the shortest jobs first. The shortest job first is only optimal only when all the jobs are availble simultaneously.

### Shortest Remaining Time Next
The scheduler always chooses the process whose remaining run time is the shortest.

## 1.4.5 Scheduling in Interactive System

### Round Robin Scheduling
Each Process is assigned a time interval, called quantum, during which it is allowed to run. If the process is still running at the end of the quantum, the CPU is preempted and given to another process. If the process has blocked or finished before the quantum has elapsed, the CPU immediately context switches to the next ready process.

Setting the quantim too short causes too many context switches and lowers the CPU efficiency, but setting it too long may cause poor response to short interactive requests.

```
CPU Efficiency = min(T, Q) / (min(T, Q) + S)
```

- T - average seconds before process gets blocked
- Q - quantum
- S - time required for a context switch

### Priority Scheduling (Dynamic)
Each process is assigned a priority and the runnable process with the highest priority is allowed to run. To prevent starvation we reduce or decrement the priority every so while so that lower priority processes gets to run.

### Multiple Queues
For systems that has high cost for context switching, we can set up multiple queues with different classes.
- Class 1 gets 1 quanta, Class 2 gets 2 quanta and Class N gets 2^N quanta.
- If a process needs 100 quanta, for round robin we will need 100 swaps potentially. But for Multiple queues, it will get 1, 2, 4, 8, 16, 32, and then 64 quanta which is only 7 swaps.

### Shortest Process Next
The shortest process next algorithm tries to predict the next shortest process by looking at past behavior.

```
S0 = T0
Sn+1 = a(Sn) + a(Tn)
```

- Sn - The estimate that was made for the nth run (past history)
- Tn - The actual time the nth run took
- Sn+1 - The new estimate for the n+1 term

### Guaranteed Scheduling
If there are n users that logged in, each one only gets 1/n of the CPU.

### Lottery Scheduling
Each process is given lottery tickets for various system resources, such as CPU time. Whenever a scheduling decision has to be made, a lottery ticket is chosen at random, and then the process holding the ticket gets the resource.

### Fair Share Scheduling
Each user is allocated some fraction of the CPU and the scheduler picks processes in such a way as to enforce it. So, if two users have each been promised 50% of the CPU, they will each get that, no matter how many processes they have in existence.

## 1.4.6 Scheduling in Real Time System
Scheduling algorithms for real time system can be different for every OS, and can be hard to come up with because it very specific.

**Hard Real Time**
- There are absolute deadlines that must be met.

**Soft Real Time**
- Missing an occasional deadlone is undesirable, but still tolerable.

**Periodic**
- Events that occur unpredictably

**Aperiodic**
- Events that occur unpredictably

**Schedulable**
- There exist a way we can schedule the process such that all process will be able to meet its deadline.

To check if such processes are schedulable it must meet the following criteria:
```
(Sum of all) C/P <= 1
```

- C - seconds of CPU time to handle each event
- P - period the event must meet its deadline.
- If it is greater than 1, then it means that the total amount of CPU time the processes want collectively is more than the CPU can deliver.

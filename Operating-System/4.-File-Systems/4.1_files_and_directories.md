## 4.1.1 Objectives
- Understand the difference between **Volatile** and **Non-volatile** memory.
- Understand the requirements for long term memory storage.
- Understand the what files and directories are.
- Understand the the concept of linking between files and directories.

## 4.1.2 Volatile and Non-Volatile Memory

| Properties | Volatile | Non-Volatile |
|---|---|---|
| Constant Power Required | Yes | No |
| Data Lifespan | Only when powered | Years without power. |
| Speed | Very Fast | Slow |
| Cost | Higher | Lower|
| Use Case | Active/temporary data | Long-term storage |
| Examples | RAM(DRAM, SRAM), CPU Cache | SSD, HDD, ROM, EEPROM |

## 4.1.3 Requirements for Long Term Memory Storage
1. **Large Capacity**, Must be able to store very large amounts of data.
2. **Persistence**, Data must survive even when the program using it is closed or computer is shut down.
3. **Concurrent Access**, Multiple programs must be able to access the same data at the same time.

## 4.1.4 Files

A file is a named collection of related data stored on persistent storage, used to retain information beyond the lifetime of a process.

Think of a text file you create on your computer. You give it a name, and inside it, you start writing notes. The file is named, contains a collection of related characters and data, and is stored on disk (non-volatile memory) meaning it persists even after you close the program or shut down you computer.

### Naming Files

 Rules on naming files depends on the Operating System. UNIX is case sensitive while MS-DOS is not. Additionally every file have a **file extension**, which indicates the file's type and what kind of data it holds (e.g. ```.txt``` for text and ```.jpg``` for images).

### File Access Types
1. **Sequential Access** - Data must be read starting from the beginning, in order. You cannot skip arround.
2. **Random Access Files** - Data can be read in any order, from any position in the file.

### File Operations
- Create
- Delete
- Open
- Close
- Read
- Write
- Append
- Seek
- Rename

### File Attributes
Every file has extra information associated with it, called **file attributes** or **metadata**. These include, owner, password, protection, size, time od creation, time last modified, time of last access, and more.


### File Types
| File Types | Description |
|---|---|
| Regular Files  | Files that contain user data, such as text files, images, executables, and more. |
| Directories | Special system files that maintain the structure of the file system by keeping track of other files. |
| Character Special Files | Related to I/O, used to model seriel devices such as terminals, printers, and network. |
| Block Special Files | Used to model storage devices such as disks. |


## 4.1.5 Directories

As mentioned, a directory (or folder) is a special kind of file that holds the names and locations of other files rather than user data.

### Single Level Directory Systems

The simplest form of directory system, where one directory contains all other files. This single directory is called the **root directory**.

### Hierarchical Directory Systems
<!-- Alright what if you want to organize your files more, a single directory will simply not do. Therefore, we can have a hierarchical directory system, where a directory can have sub directories and the sub directories can have even more sub directories or even other file types. -->
A single directory becomes impractical when you have many files to organize. A hierarchical directory system solves this by allowing directories to contain **subdirectories**, which can contain even more subdirectories or files forming a treestructure. This is how modern operating systems organize files.

### Path Names

| Path Type | Description | Example |
|---|---|---|
| Absolute Path | Full path to a file starting from the root directory. Always works regardless of where you are. | ```/usr/ast/mailbox```|
| Relative Path | Path to a file starting from your current working directory. Shorter, but depends on where you are in the file system. | ```mailbox``` (if you're already in ```/usr/ast```)|
| Working Directory (Current Directory)| The directory you are currently located in within the file system. | ```/usr/ast```|

### Linking

| Link Type | Description |
|---|---|
| Hard Link | A direct reference to a file, allowing the same file to appear in multiple directories. The file is only deleted when all hard links pointing to it are removed.|
| Symbolic Link (Soft Link)| A reference to another file by path name rather than directly to the data. More flexible than hard links as they can point to files across different disks or even remote computer but slightly less efficient. |

### Linking Ananlogy

| Object | Represents|
|---|---|
| Room |  The actual data or file. |
| Door | A hard link that directly reference a file. |
| Sign | A symbolic link that points to a file by their path name. |

Hard Link - Think of a file as a room. A hard link is simply another door into that same room. A room can have multiple doors, but it's still the same room. the room only disappears when every single door is removed.

Symbolic Link - Rather than a door, a symbolic link is a sign that points you to the right door. If the original door (hard link) is removed, the sign becomes useless as it no longer leads anywhere.

> [!Note]
> Simply put hard link points to the actual data on disk, while symbolic link (soft link) points to the location/path of the data and not the data itself.
